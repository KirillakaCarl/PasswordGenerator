# Учебный порядок работы с Git и Pull Request

Pull Request создаёт и описывает пользователь. Codex помогает разбирать
изменения и проверять текст, но не создаёт и не объединяет PR за пользователя.

## Ветки и версии

- main содержит хранилище из PR #2 (0.3.0-beta.1); прежние беты
  доступны по меткам v0.1.0-beta.1 и v0.2.0-beta.1.
- codex/password-assessment использовалась для PR #1 с оценкой сложности.
- codex/encrypted-storage использовалась для PR #2 с хранилищем.
- codex/vault-search содержит поиск, даты и сортировку.
- Кандидат следующего выпуска: 0.4.0-beta.1. Добавлена новая функция, поэтому
  в рамках нашего проекта увеличиваем MINOR: 0.3 → 0.4. Это договорённость
  для начальной разработки; SemVer допускает нестабильный API до 1.0.0.
- Суффикс beta.1 означает первый предварительный выпуск этой версии.
- Версия записана в password_generator/__init__.py; изменения — в CHANGELOG.md.
- PR #1 объединён пользователем; дальнейшие PR проходят те же шаги.
- Метка выпуска создаётся после проверки и объединения. Уже выпущенная метка
  v0.1.0-beta.1 не перемещается и её содержимое не меняется.

PEP 8 регулирует стиль Python: отступы, имена, импорты, переносы и комментарии.
Он не устанавливает формат Git-коммитов, PR или номеров версий. Для номеров
используем Semantic Versioning, для описаний — правила ниже.

Официальные источники:

- https://peps.python.org/pep-0008/
- https://semver.org/

## Перед публикацией рабочей ветки

1. Проверить приложение вручную на искусственных данных.
2. Запустить тесты: `.venv/Scripts/python.exe -m unittest discover -v`.
3. Посмотреть `git status` и `git diff`: в изменениях нет секретов и временных файлов.
4. Создать содержательный коммит: кратко назвать добавленное поведение.
5. Отправить рабочую ветку на GitHub. Коммит и отправка не создают PR автоматически.

## Самостоятельный Pull Request

На GitHub выбрать создание Pull Request: base — main, compare —
codex/vault-search. Сначала просмотреть Files changed и коммиты.
Ниже ориентиры для собственного текста; это не готовый PR.

Заголовок отвечает на вопрос «что изменится для пользователя?».
В описании отразить:

1. Задачу: в большом хранилище было сложно найти нужную запись.
2. Результат: поиск по названию, отображение даты создания, сортировка.
3. Принцип: фильтрация в памяти, сравнение дат с часовыми поясами, UUID строк.
4. Проверки: реально выполненные тесты и ручные сценарии.
5. Ограничения: поиск только по названию; дата относится к сохранению записи.
6. Версию: кандидат 0.4.0-beta.1; метка появится после проверки выпуска.

Комментарии к конкретным строкам объясняют причину решения или задают вопрос.
Описание PR объясняет весь результат. Не нужно пересказывать каждую строку кода.

Перед объединением можно прислать текст PR в чат для проверки наставником.
Открытие PR, объединение и выпуск — отдельные действия; публикация ветки сама
по себе не заменяет их.
