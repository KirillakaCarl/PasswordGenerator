# Как разбирать код для защиты

Проверка текущей версии: 31.10.2026. В основных модулях и тестах у всех классов
и именованных функций есть docstring. Комментарии дополнены после чтения кода,
а не только проверки наличия описаний. Новые функции потребуют новой проверки.

| Порядок | Файл и место | Что объяснить |
| --- | --- | --- |
| 1 | main.py: main | Создание одного окна и передача управления циклу событий |
| 2 | gui.py: _build_widgets, _generate | Виджеты связаны с переменными; кнопка вызывает обработчик, он передаёт настройки независимому алгоритму |
| 3 | generator.py: generate_password | Общий алфавит, secrets, проверка каждой группы и повтор выбора кандидата |
| 4 | assessment.py: assess_baseline, assess_password | Учебные баллы за длину и группы, затем ограничения за распознанные шаблоны |
| 5 | encryption.py: derive_cipher, decrypt_payload | Мастер-пароль превращается в ключ с солью; Fernet проверяет подлинность и расшифровывает |
| 6 | storage.py: open, _write, _atomic_write | Проверки до и после расшифрования, шифрование всего списка, запись через временный файл |
| 7 | storage_ui.py: _start, _poll | Поток выполняет операцию, очередь передаёт результат, основной поток обновляет виджеты |
| 8 | storage.py: lock; gui.py: _clear_secrets | Завершение сеанса убирает ссылки на ключ и очищает поля, но не гарантирует обнуление памяти |
| 9 | tests/ | Искусственные примеры, границы, неверные параметры, повреждение файла и отказ записи |

Для короткого выступления читать выбранные пояснения рядом с показом
соответствующего действия приложения. Докстринги описывают контракт функций,
комментарии перед блоками объясняют причины решений и порядок действий.
Фактические ограничения алгоритма оценки и хранения также проговариваются.
