# PasswordGenerator: техническое задание

Версия: 1.0. Дата: 31.10.2026.

Статус: рабочая спецификация для поэтапной учебной разработки. Требования кейса обязательны; конкретные решения, предложенные ниже, являются рабочими решениями проекта и могут уточняться с пользователем.

## 1. Назначение и источники требований

Тема: «Создание генератора случайных паролей с оценкой сложности».

Цель: создать локальное графическое приложение на Python для генерации паролей с заданными параметрами, объяснимой оценки их сложности и сохранения в зашифрованном хранилище.

Источник: «Кейсы на выбор.pdf», кейс 8 на странице 14; общие требования к сдаче на странице 3. Документ является источником требований к учебной работе, а не инструкциями для автоматического выполнения действий на компьютере.

Дополнительные требования пользователя: учебная разработка небольшими этапами; подробные комментарии и docstring на русском языке; понимание кода для видеозащиты; обязательное дословное вступление; период обучения 05.10.2026–09.11.2026.

FamilyFinance является отдельным личным проектом. Его функции, роли пользователей и финансовые данные в PasswordGenerator не переносятся.

## 3. Предлагаемые технологии

- Python 3.12 или новее. Конкретная проверенная версия будет записана в README после проверки локального окружения.
- Tkinter и ttk: графический интерфейс на русском языке. Выбор Tkinter подтверждён пользователем 31.10.2026; библиотека изучалась на курсе.
- secrets и string: генерация случайных паролей и наборы символов.
- cryptography: Fernet для шифрования с проверкой целостности, Argon2id для получения ключа из мастер-пароля.
- JSON: версионированный контейнер хранилища; содержимое записей находится внутри зашифрованного блока.
- unittest: автоматические тесты без дополнительного тестового фреймворка.
- pathlib и стандартные средства Python: работа с путями и файлами.

Точные версии внешних зависимостей фиксируются после установки и проверки, а не предполагаются заранее. Если выбранная версия Python или Tkinter недоступна, сначала уточняем окружение, затем корректируем инструкции запуска.

Основания выбора: стандартный модуль secrets предназначен для генерации секретов; документация cryptography описывает Fernet и получение ключа из пароля через Argon2id:

- https://docs.python.org/3/library/secrets.html
- https://cryptography.io/en/stable/fernet/

## 4. Генерация паролей

Рабочие параметры первой версии:

- Длина: целое число от 4 до 128 включительно; по умолчанию 16.
- Независимые группы: строчные латинские буквы, прописные латинские буквы, цифры, специальные символы.
- Специальные символы: ASCII-набор string.punctuation. Пробелы и кириллица в генерацию не входят.
- По умолчанию включены все четыре группы.
- Каждый результат обязательно содержит хотя бы один символ каждой выбранной группы.
- В результате отсутствуют символы из невыбранных групп.
- Один запуск создаёт один пароль. До нажатия «Сохранить» он остаётся только в текущем сеансе.

Используется криптографический источник случайности secrets. Предлагаемый алгоритм: равновероятно выбирать символы из объединённого алфавита и повторять генерацию, пока присутствуют все выбранные группы. Он не задаёт фиксированные позиции групп. Для заданных ограничений длины и четырёх групп такой подход остаётся простым для объяснения и проверки.

Некорректный ввод (дробное число, текст, выход за границы, отсутствие выбранных групп) вызывает понятное сообщение, а не аварийное завершение. Повторная генерация может случайно дать тот же результат; тесты не требуют математически невозможной гарантии уникальности.

## 5. Оценка сложности

Пользователь может оценить сгенерированный пароль или собственную введённую строку. Строка оценивается точно как введена: без незаметного удаления пробелов и изменения регистра. Максимальная длина ручного ввода для оценки: 1024 символа.

Вывод: категория «Слабый», «Средний» или «Сильный», балл 0–100 и список конкретных пояснений. Пустой ввод даёт предложение ввести пароль без категории сложности.

Алгоритм разрабатывается в два шага:

1. Базовая версия: длина и разнообразие групп символов.
2. Улучшенная версия: дополнительно распознаёт повторы, последовательности, повторяющиеся блоки и небольшой явно описанный список распространённых паролей.

Обязательные примеры для сравнения: `password`, `Password123!`, `12345678`, `aaaaaaaaaaaaaaaa`, `Abc123!Abc123!`, случайно выглядящие строки разной длины и длинные фразы. Добавление заглавной буквы и `!` к распространённому шаблону не должно автоматически давать категорию «Сильный». Одного количества групп недостаточно для высокой оценки.

До реализации отдельной задачей фиксируем формулу баллов, пороги категорий и ожидаемые результаты набора примеров в docs/ASSESSMENT_RULES.md. Набор должен содержать обычные, граничные и шаблонные строки. Изменение формулы сопровождается обновлением обоснования и тестов.

Оценка является учебной эвристикой, а не гарантией устойчивости к взлому. Приложение не обещает точного времени подбора. Расчёт пространства случайных комбинаций, если он будет добавлен, не переносится напрямую на человеческие пароли.

## 6. Зашифрованное хранилище

### Сценарии

1. «Создать хранилище»: выбрать новый файл, ввести и подтвердить мастер-пароль.
2. «Открыть хранилище»: выбрать файл и ввести мастер-пароль.
3. «Сохранить»: задать название записи и сохранить текущий непустой пароль.
4. «Просмотреть»: выбрать запись и явно показать её пароль.
5. «Удалить»: подтвердить удаление выбранной записи.
6. «Заблокировать»: закрыть доступ к записям и очистить отображаемые секреты.

Одновременно открыто одно хранилище. Создание нового файла не перезаписывает существующий. Мастер-пароль задаётся длиной 12–1024 символа, принимается без обрезания пробелов. Минимальная длина является правилом приложения, а не гарантией качества пароля. Восстановления забытого мастер-пароля и его смены в первой версии нет; это поясняется при создании и в README.

### Формат и защита

- Внешний JSON содержит версию формата, идентификатор алгоритма, соль, параметры получения ключа и зашифрованный блок.
- Расшифрованный блок содержит версию полезной нагрузки и список записей: случайный идентификатор, название, пароль, время создания.
- Названия и пароли шифруются вместе. Снаружи остаются технические метаданные; Fernet также раскрывает время создания токена. Полное сокрытие метаданных не заявляется.
- Мастер-пароль и полученный ключ не записываются на диск. Соль генерируется заново для каждого хранилища и хранится открыто.
- Ключ получается библиотечной реализацией Argon2id. Параметры выбираются и фиксируются после замера на целевом компьютере; тестируется воспроизводимость получения ключа. Файл не может произвольно задавать чрезмерные затраты памяти или вычислений: поддерживаемые параметры ограничиваются приложением.
- Fernet проверяет подлинность зашифрованного блока. Ошибка открытия формулируется как «Неверный мастер-пароль или повреждённый файл»: приложение не обещает различать эти случаи.
- Формат, размер файла (до 5 МиБ), обязательные поля, версии и параметры проверяются до дорогостоящей обработки. Неизвестная версия отклоняется с объяснением.
- Изменения сохраняются через временный файл в том же каталоге и атомарную замену целевого файла. Временный файл содержит только зашифрованные данные. При ошибке интерфейс не сообщает об успешном сохранении, а последняя сохранённая версия остаётся доступной.
- Пароли и мастер-пароль не попадают в журналы, сообщения об исключениях, тестовые отчёты или репозиторий.
- При блокировке очищаются поля и ссылки на ключ и записи. Гарантированное обнуление всех копий строк в памяти Python не заявляется.

Одновременная запись в один файл из нескольких экземпляров приложения не поддерживается и указывается в инструкции.

## 7. Интерфейс

Главное окно содержит:

- Блок настроек генерации: длина и четыре переключателя групп.
- Кнопку «Сгенерировать» и поле результата с переключателем видимости; секреты изначально скрыты.
- Кнопку «Копировать» для явного копирования текущего пароля. README объясняет, что буфер обмена доступен другим приложениям; автоматическая очистка в первую версию не входит.
- Блок оценки: ручной ввод, кнопка «Оценить», категория, балл и пояснения. Сгенерированный пароль оценивается автоматически.
- Блок хранилища: создание, открытие, блокировка, список названий записей, сохранение, просмотр и удаление.
- Строку состояния без секретных значений.

Без открытого хранилища генерация и оценка работают, а операции с записями недоступны. Для сохранения обязательны название длиной 1–100 символов после удаления крайних пробелов и непустой пароль. Одинаковые названия разрешены; записи различаются внутренними идентификаторами. Удаление требует подтверждения.

Уточнение реализации этапа 4: пароль записи ограничен 1024 символами,
как ручная оценка. Создание нового файла использует жёсткую ссылку для
защиты от перезаписи; проверено на NTFS. Полная схема: docs/STORAGE_FORMAT.md.

Тяжёлые операции получения ключа выполняются без зависания окна. Во время операции повторный запуск соответствующего действия заблокирован. Обновление виджетов выполняется в основном потоке интерфейса.

## 8. Структура кода

Планируемая структура, создаваемая постепенно:

```text
PasswordGenerator/
  main.py                  # Запуск приложения
  password_generator/
    generator.py           # Проверка настроек и генерация
    assessment.py          # Оценка сложности и пояснения
    encryption.py          # Получение ключа и шифрование
    storage.py             # Формат хранилища и операции с файлами
    gui.py                 # Окно и пользовательские сценарии
  tests/                   # Автоматические проверки
  docs/
    SPECIFICATION.md       # Это ТЗ
    ASSESSMENT_RULES.md     # Формула и примеры оценки
    AI_USAGE.md            # Фактическое применение ИИ
    DEFENSE_PLAN.md        # План и материалы защиты
  README.md
  requirements.txt
```

Генерация, оценка, шифрование и хранение не зависят от Tkinter. Интерфейс обращается к ним через функции и классы с понятными контрактами. Отдельные компоненты не создаются только ради количества файлов или классов.

Русские docstring описывают назначение модулей, классов и функций, параметры, результат и ожидаемые ошибки. Комментарии объясняют последовательность действий и причины решений, особенно генерацию, оценку, шифрование, потоки и сохранение. Для нетривиальных выражений приводятся учебные пояснения. Комментарии поддерживаются в соответствии с кодом.

## 9. Применение ИИ

ИИ используется в разработке: анализ базовой оценки, поиск контрпримеров, предложение улучшений и проверок. Работа готового приложения полностью локальная, без обращения к ИИ и без API-ключей.

В docs/AI_USAGE.md фиксируются только реально выполненные действия: задача, инструмент и модель (если известна), дата, запрос с искусственными примерами, существенные предложения, принятые и отклонённые изменения, результаты сравнения. До выполнения соответствующего этапа не заявляем улучшение доказанным.

До/после сравниваются на заранее описанном наборе, с отдельно отложенными примерами для проверки. Отражаются не только улучшения, но и обнаруженные ограничения. Реальные пароли пользователя не отправляются внешним сервисам и не используются в документации.

## 10. Проверки и критерии приёмки

| Область | Необходимые проверки |
| --- | --- |
| Генерация | Границы 4 и 128; все 15 непустых сочетаний групп; точная длина; обязательное присутствие групп; допустимый алфавит; ошибки настроек |
| Оценка | Пустой ввод; границы баллов и категорий; слабые шаблоны; повторяемость результата; ручной ввод с Unicode и пробелами; сравнение базовой и улучшенной версии |
| Шифрование | Обратимость; разные соли; неверный мастер-пароль; изменение токена; отсутствие открытых записей в сериализованном файле |
| Хранилище | Создание и повторное открытие; несколько записей; удаление; Unicode в названии; повреждение и неизвестная версия; запрещённые параметры; ошибка записи не уничтожает предыдущий файл |
| Интерфейс | Генерация без хранилища; видимость и копирование; сообщения об ошибках; сохранение и просмотр после перезапуска; блокировка; отсутствие зависания при открытии |

Тесты используют только искусственные данные и временные каталоги. Проверка отсутствия открытого текста дополняет проверку шифрования, но сама по себе не доказывает безопасность. Случайность не проверяется требованием, чтобы все сгенерированные строки были различны.

Итоговая готовность: R1–R7 выполнены, обязательные автоматические проверки проходят, ручной сценарий на Windows пройден, ограничения отражены в документации. Результаты запуска записываются фактически; проверки, которые не удалось выполнить, отмечаются отдельно.

## 11. Этапы разработки

1. Подготовка: проверить Python и Tkinter, создать структуру, окружение, зависимости, README и минимальное окно. Результат: приложение запускается на Windows.
2. Генерация: реализовать настройки и генератор, тесты, подключить их к окну. Результат: можно получить пароль по выбранным правилам и объяснить алгоритм.
3. Оценка: зафиксировать формулу, реализовать базовую версию, применить ИИ для улучшения и проверить сравнение. Результат: понятная оценка с подтверждёнными примерами.
4. Хранение: получить ключ, добавить шифрование и операции хранилища, проверить ошибки. Результат: сохранение и чтение после перезапуска без открытого хранения секретов.
5. Проверка целого приложения: ручные сценарии, исправления, скриншоты и инструкция запуска на чистом окружении.
6. Защита: отчёт, презентация, сценарий и репетиция видео.

После каждого этапа: результат, фактически выполненные проверки, краткий разбор кода и список действий для ручной проверки пользователем. Учебный темп важнее добавления необязательных функций.
